# Участие в проекте

Спасибо за интерес к Live Hints. Небольшие исправления, отчёты о совместимости и аккуратные улучшения документации здесь так же важны, как новые функции.

## Перед началом

1. Проверьте, нет ли уже похожей задачи или запроса на изменение.
2. Для крупной идеи сначала создайте задачу с описанием сценария, ограничений и ожидаемого результата.
3. Не добавляйте реальные записи разговоров, резюме, ключи API и другие персональные данные.

## Ветка и коммит

Работайте в отдельной ветке от актуального `main`:

```powershell
git switch main
git pull --ff-only origin main
git switch -c dev_краткое_название_shev
```

Для исправления используйте префикс `fix_`, для новой функции или доработки — `dev_`. Сообщение коммита пишется на русском языке, начинается с глагола совершенного вида с большой буквы и не содержит префиксов вроде `feat:` или `fix:`.

## Проверки перед запросом на изменение

```powershell
npm run lint
npm test -- --runInBand
npm run test:python
npm run test:e2e
git diff --check
```

Если проверка требует Ollama, CUDA или аудиоустройство, укажите это в описании результата. Не маскируйте пропуск проверки зелёным статусом.

## Запрос на изменение

В описании укажите:

- какую проблему решает изменение;
- как воспроизвести старое поведение и проверить новое;
- какие файлы затронуты;
- какие ограничения или риски остались;
- какие проверки были запущены.

Изменения должны быть небольшими и связанными одной задачей. Не смешивайте исправление поведения с массовым форматированием.

## Границы проекта

- аудио и пользовательский контекст не должны уходить в облако без явного отдельного решения;
- все ошибки компонентов должны сохранять `trace_id` для корреляции;
- целевой показатель задержки 500 мс является инженерным ориентиром, но не рекламным обещанием;
- интерфейс и документация не содержат эмодзи или текстовых псевдоиконок.
